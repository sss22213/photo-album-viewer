# Photo Album

> **Note:** This project is **AI-generated** (built with [Claude Code](https://claude.com/claude-code)). Use, audit and adapt accordingly.

A self-hosted photo album viewer. Register any directory on your machine as an album source, browse generated thumbnails, and view full-size photos from desktop or mobile. Vue 3 + Vite on the frontend, Node.js + Express on the backend, Sharp for thumbnails, packaged with Docker.

## Features

- **Multi-source library** — register any directory as a "source". Every subfolder beneath it automatically becomes an album.
- **Manual albums** — add a single folder as an album without creating a source.
- **Thumbnail cache** — 400×400 JPEG thumbnails generated by Sharp, cached on disk for fast subsequent loads.
- **Path autocomplete** — when adding a source, typing a directory shows matching subfolders as suggestions (mouse or ↑/↓/Enter to pick).
- **Multi-album merged view** — select multiple albums and view their photos together in a single grid.
- **Mobile-friendly** — two columns on phones, robust square layout that avoids iOS Safari aspect-ratio quirks, scroll position is restored when returning from a photo to the album list.
- **Keyboard navigation** — in the photo preview overlay use ← / → to switch photos and Esc to close.
- **Internationalization (i18n)** — UI available in **English, Traditional Chinese (繁體中文), Simplified Chinese (简体中文), Japanese (日本語), and German (Deutsch)**. The language is detected from the browser on first load and remembered in `localStorage`.

## Requirements

- Docker and Docker Compose (recommended)
- Or local Node.js 20+ for a non-containerised run

## Quick start (Docker)

1. Clone the repository:

   ```bash
   git clone https://github.com/<your-account>/photo-album.git
   cd photo-album
   ```

2. Edit `docker-compose.yml` and point the photo volume at your own directory:

   ```yaml
   volumes:
     - photo-album-data:/app/cache
     - /your/photo/path:/photos:ro     # ← change this
   ```

3. Build and start the container:

   ```bash
   docker compose up --build -d
   ```

4. Open [http://localhost:3001](http://localhost:3001).

5. Go to **Settings → Album Sources** and add `/photos` (or any subdirectory of it) as a source. After the scan finishes, your albums will appear on the home page.

### Changing the port

Update both the published port and the `PORT` environment variable in `docker-compose.yml`:

```yaml
ports:
  - "8080:8080"
environment:
  - PORT=8080
  - IMAGE_DIR=/photos
```

## Persistent data

All runtime state lives under `/app/cache` so a single named volume keeps everything:

| Path                              | Purpose                             |
| --------------------------------- | ----------------------------------- |
| `/app/cache/manifest.json`        | Cached album and file manifest      |
| `/app/cache/thumbnails/`          | Generated thumbnails                |
| `/app/cache/settings.json`        | Source list and enabled albums      |

The `docker-compose.yml` mounts a named volume `photo-album-data` at `/app/cache`.

> **Important:** never bind-mount a volume over `/app` — it will shadow the `node_modules` and server code baked into the image and the container will fail to start.

## API reference

| Method | Path | Description |
| ------ | ---- | ----------- |
| GET    | `/api/settings`                           | Get sources and enabled albums |
| PUT    | `/api/settings`                           | Replace settings |
| GET    | `/api/sources`                            | List sources (with their albums) |
| POST   | `/api/sources`                            | Add a source `{ name, albumPath }` |
| DELETE | `/api/sources/:name`                      | Remove a source and its albums |
| GET    | `/api/browse?path=...`                    | Directory-path autocomplete |
| GET    | `/api/albums`                             | List visible albums |
| GET    | `/api/albums-manifest`                    | List all albums (including disabled) |
| POST   | `/api/scan`                               | Rescan all sources and rebuild thumbnail cache |
| POST   | `/api/albums`                             | Add a manual album `{ name, path }` |
| DELETE | `/api/albums/:source/:name`               | Remove an album |
| GET    | `/api/albums/thumb?album=&filename=`      | Get a 400×400 JPEG thumbnail |
| GET    | `/api/albums/img?album=&filename=`        | Get the full-size image |
| GET    | `/api/albums/:album/photos`               | List photos in an album |

## Tech stack

- **Frontend:** Vue 3 (`<script setup>`), Vue Router 4, vue-i18n 10, Vite
- **Backend:** Express 5, Multer, Sharp
- **Container:** Docker, Docker Compose (multi-stage build)

## Adding a new language

1. Add `src/i18n/locales/<code>.json` (copy `en.json` as a template).
2. Register it in `src/i18n/index.js`: add it to `SUPPORTED_LOCALES`, the `messages` object, and (optionally) `detectLocale`.
3. Add a `language.<code>` label in every existing locale file.
4. Rebuild.

## Development tips

- After backend changes, rebuild the container: `docker compose up --build`.
- After frontend changes, the same `--build` runs the Vite build stage.
- Tail logs: `docker compose logs -f photo-album`.
- Regenerate thumbnails: **Settings → Rescan Albums**.
